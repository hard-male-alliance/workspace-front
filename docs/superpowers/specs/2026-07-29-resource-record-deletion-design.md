# 简历、模拟面试与知识库记录删除设计

## 目标

为简历、模拟面试历史和知识库来源增加永久删除入口，同时保持现有权限、并发保护、异步任务、实时面试和简历 PDF 流程不变。

删除以服务端权威结果为准。前端不得通过隐藏记录伪造成功，也不得绕过工作区授权、资源版本或状态校验。

## 统一交互

- 在三类记录的现有列表项操作区增加“删除”入口。
- 删除前显示不可恢复确认框，并展示记录名称。
- 请求期间禁用重复提交。
- 服务端确认成功后再移除记录。
- 删除失败时保留记录，并展示可理解的错误。
- 删除当前正在查看的记录后返回对应列表。

不引入通用资源删除框架。确认框可以复用公共组件，但三种资源继续通过各自的领域 Gateway 表达删除语义。

## 简历

后端现有简历删除接口保持不变。前端为 `ResumeGateway` 增加按当前 revision 删除简历的能力，并由 HTTP adapter 使用强 `If-Match` 条件调用现有端点。

- `204`：从列表移除。
- `404`：重新读取列表；资源已经不存在。
- `412`：提示服务器版本已变化，要求刷新。
- 其他失败：保留记录并允许重试。

本次不修改简历 PDF 权威展示、版本生成或 Agent proposal 流程。

## 模拟面试

新增单场面试永久删除能力，只允许删除终态会话。进行中、连接中、正在结束或正在生成报告的会话不能删除，必须先结束。

后端在一个事务中完成：

1. 校验工作区成员和资源权限；
2. 锁定或校验面试会话当前状态；
3. 拒绝非终态会话；
4. 删除实时连接和输入记录；
5. 删除转录片段；
6. 删除报告证据和报告；
7. 删除会话本身。

任一步骤失败时整体回滚。前端只在成功响应后移除历史记录。新端点、错误结构和契约副本必须同步更新，页面不得写死 transport 细节。

## 知识库

复用现有异步删除 Job。前端为 `KnowledgeGateway` 增加删除来源能力：

1. 提交带当前 revision 的删除请求；
2. 收到 `202` 后进入 `deleting`；
3. 禁用打开、重新解析和重复删除；
4. 复用现有 Job 查询/恢复机制；
5. Job 成功后移除来源；
6. Job 失败后恢复可操作状态并展示错误。

刷新后若服务端仍返回 `deleting`，页面继续展示真实状态，不恢复为普通记录。

## 错误与安全

- `401/403`：提示没有权限。
- `404`：重新加载列表。
- `409`：展示资源状态冲突。
- `412`：展示版本冲突并要求刷新。
- 网络错误：保留记录并允许重试。
- 服务端必须执行对象级授权，不能依赖前端按钮可见性。
- 删除命令保持幂等，不因重试产生额外副作用。
- 日志不得记录简历正文、面试转录、知识库原文或其他用户自由文本。

## 测试与提交

按照测试驱动开发执行最小定向验证：

1. 后端先覆盖终态面试可删除、非终态拒绝和关联数据清理，再实现接口；
2. 前端分别覆盖简历同步删除、面试删除和知识库异步删除；
3. 每个测试先确认因能力缺失而失败，再写最小实现；
4. 每个模块形成独立提交，不运行无关全量测试。

计划提交顺序：

1. `docs: design resource record deletion`
2. `feat(interview): delete terminal interview sessions`
3. `feat(resume): delete resume records`
4. `feat(interview): delete interview history records`
5. `feat(knowledge): delete knowledge sources`
