# RoleStory 前端壳层与简历编辑器精简设计

## 目标

在不改变后端接口、工作区权限、简历保存、AI 修改、版本冲突处理和真实 PDF
生成流程的前提下，删除无实际用途的界面元素，并改善简历编辑器的信息密度和多板块编辑体验。

## 范围

本次只修改 `workspace-front`。改动分为三个相互独立的部分：

1. 全局壳层与工作台精简；
2. 简历中栏板块展开体验；
3. PDF 预览成功状态精简。

不修改工作区领域模型、Gateway、HTTP DTO、后端代码、PDF 权威展示策略或简历领域数据结构。

## 全局壳层与工作台

### 品牌

- 将所有用户可见的 `Inkwell` 文案统一为 `RoleStory`。
- 同步修改登录页、启动失败页和中英文无障碍名称。
- 保留内部 npm 包名、CSS `aw-` 前缀、目录名和领域类型，避免无关重命名。
- 现有品牌图形标记保持不变。

### 删除的展示

- 删除无实际功能的“反馈”按钮、不可用说明和对应隐藏描述。
- 删除工作台中的角色、套餐、数据区域展示。
- 删除工作台底部“数据来自当前工作区，操作结果以服务端确认为准。”说明。
- 左下角账户区域只保留头像和当前登录账户名；删除工作区名称、角色、套餐、数据区域和桌面版附加说明。
- 删除右上角完整的工作区选择控件、加载更多按钮及其界面错误提示。

工作区访问数据、分页读取、当前工作区 Session 和 `selectWorkspace` 领域能力继续保留。应用仍使用
Session 初始化得到的当前工作区。本次不删除未来恢复多工作区入口所需的底层能力。

## 简历中栏

### 个人信息

个人信息继续使用独立的 `resume.profile` 数据和现有窄保存命令，不转换成普通 `section`。
展示层改用与其他板块一致的卡片、标题栏、背景和展开视觉。因为个人信息是固定资料：

- 不显示拖动手柄；
- 不提供上移、下移和删除；
- 不改变姓名、职业标题、个人简介和联系方式的保存逻辑。

### 多板块展开

将单一 `focusedSectionId` 替换为独立展开集合。每个板块点击标题后独立切换展开状态，
打开一个板块不会关闭其他板块。个人信息也拥有独立的展开状态。

初始状态保持信息可用：个人信息和第一个普通板块默认展开。权威重载、板块删除或新增后，
展开集合只保留仍然存在的板块标识，不参与简历持久化，也不改变草稿和并发保护。

板块正文、结构化条目、拖动排序、上下移动、删除、失焦保存和草稿恢复继续复用现有实现。

## PDF 预览

成功生成且 Artifact 已加载后，不再常驻显示：

- “PDF 已生成。”
- “N 页 · N MB”

以下状态继续显示：

- 排队和生成进度；
- PDF 安全加载进度；
- 失败、取消和过期；
- PDF 落后于当前简历版本；
- 恢复任务、取消任务和保存失败等现有错误。

PDF 按钮、下载按钮、Artifact 校验、真实 PDF iframe、版本匹配和权威资源读取逻辑均保持不变。

## 测试

按测试驱动开发执行最小定向验证：

1. 壳层测试先证明品牌、反馈、账户摘要和工作区选择器仍按旧行为出现，再改为新期望。
2. 工作台测试覆盖权限摘要和底部说明移除。
3. 简历编辑器测试覆盖个人信息视觉结构、多个板块同时展开以及独立关闭。
4. PDF 预览测试覆盖成功状态和元数据隐藏，并确认失败、进度和过期状态仍可见。
5. 运行相关 DOM 测试、TypeScript 检查、Lint 和格式检查；不进行无关全量格式化。

## 风险控制

- 只删除工作区切换的 UI，不删除工作区 Session 和权限数据。
- 不把 `profile` 合并进 `sections`，避免破坏 PDF 数据映射。
- 展开状态只属于浏览器展示层，不进入后端命令或并发令牌。
- 只隐藏 PDF 成功后的冗余文字，不隐藏错误和过程反馈。
- 更新中英文资源及受影响测试，保持 Web 与 Electron 共用页面一致。
